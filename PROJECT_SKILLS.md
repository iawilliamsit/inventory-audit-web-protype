# Skills Demonstrated

This project represents my first attempt to use programming to solve a practical problem from my own work.

The application was created independently while I was learning HTML, CSS, and JavaScript. It was not an assigned development project. I identified the inventory problem, determined what information I needed, researched how to build the required functions, tested the results, and used the finished prototype during inventory auditing.

## Process Analysis

I started with an existing manual inventory process that tracked products, quantities on hand, and minimum inventory requirements.

I broke that process into specific information the application could use:

- Product name
- Items per box or case
- Number of boxes or cases
- Individual items
- Damaged inventory
- Minimum required inventory
- Current usable inventory
- Reorder status

This allowed the application to turn physical counts into a consistent inventory result.

## Practical Programming

I used HTML, CSS, and JavaScript to create a working browser-based tool.

The project required me to work with:

- HTML tables and form inputs
- CSS layout and presentation
- JavaScript variables
- Functions
- Event listeners
- Conditional logic
- Mathematical calculations
- Input values
- Output fields
- Repeated testing and debugging

## Troubleshooting and Debugging

The application contained many similar inventory rows, which made identifiers and calculations important.

When one section produced incorrect results, I worked through the affected code, compared working and non-working sections, corrected conflicting identifiers or logic, and tested the calculation again.

This taught me to isolate problems rather than continuously changing unrelated parts of the application.

## Operational Use

I used the prototype as part of my own inventory-audit workflow.

Physical inventory counts could be entered into the application and compared against established minimum quantities.

This helped me:

- Process inventory counts more efficiently
- Reduce repetitive manual calculations
- Account for damaged inventory
- Identify shortages
- Recognize when additional inventory was not necessary
- Prepare cleaner inventory information for shipment and ordering decisions
- Consider expected supply usage between inventory counts and future deliveries

## Independent Learning

I did not know everything required to build the application before starting it.

I used:

- Google searches
- YouTube programming material
- Personal study notes
- Documentation
- Existing code examples
- Experimentation
- Testing

Instead of searching for a complete inventory application to copy, I researched individual problems and adapted what I learned to the workflow I was trying to create.

## What This Project Demonstrates

This project demonstrates my ability to:

- Identify an operational problem
- Understand an existing process
- Break a larger problem into smaller technical requirements
- Research unfamiliar technical concepts independently
- Apply programming concepts to a real workflow
- Test calculations and application behavior
- Troubleshoot problems through repeated observation
- Create documentation around technical work
- Build a functional tool around a specific user need

The project began as a way to learn programming, but it also became an early example of how I approach technology: understand the problem first, determine what the system needs to accomplish, and learn the technical pieces required to make it work.
